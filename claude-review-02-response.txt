## 2. Can a validation failure still overwrite an output file?

**Demonstrated, in the normal case: no.** I put sentinel text in all four output files and fed in a duplicate ID. The script exited with an `AssertionError` and `summary.json` still held the sentinel. Your three rejection tests check the same thing for a short row, bad event order and duplicate IDs.

**Demonstrated, one real hole:** your checks are `assert` statements, and Python removes them when run as `python -O`. I ran the same duplicate-ID file with `-O`. The script exited 0, accepted the bad data, and overwrote the outputs. Normal runs are safe, but the protection depends on how the script is launched.

**Suggestions, not demonstrated:**
- Replace `assert` with `raise ValueError(...)` for the source-data checks.
- Write each output to a temporary file, then rename it. A crash halfway through the four writes could currently leave a mix of old and new files.
- Add tests for an unparseable timestamp and for "credit without confirmation". The code handles both, but nothing tests them.
