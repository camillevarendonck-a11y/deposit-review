## Verified bugs

### 1. An extreme timestamp crashes the request and the browser shows only "Failed to fetch"
- **Where:** `engine.py:20` and `server.py:75`.
- **Reproduce:** a row with `initiated_at` = `0001-01-01T00:00:00+05:00`.
- **What happens:** `astimezone(utc)` raises `OverflowError`. The server only catches `ValueError`, `TypeError` and `UnicodeDecodeError`, so it drops the connection (curl got an empty response). The CLI prints a raw traceback.
- **Fix:** in `timestamp()`, catch `OverflowError` and raise the same `ValueError`. In `do_POST`, add a final `except Exception` that returns a JSON 500.

### 2. Percentages round half-to-even instead of half-up (minor)
- **Where:** `engine.py:112` and `engine.py:126`, using Python's `round()`.
- **Reproduce:** 1 of 16 deposits within target is exactly 6.25%, and it displays as 6.2%.
- **Fix:** use `Decimal(...).quantize(Decimal('0.1'), ROUND_HALF_UP)`, or document the rounding.

### 3. Validation is looser than the documentation says (minor)
- **Where:** `engine.py:52` and `engine.py:16`.
- **What I saw:**
  - Amounts like `1_000` and full-width digits (`１００`) are accepted.
  - Date-only timestamps (`2026-11-10`) are accepted. Python 3.11+ is lenient here.
  - IDs `a` and `A` count as distinct.
- **Fix:** match amounts against `^\d+(\.\d+)?$`. Require a `T` and a time in timestamps. Decide whether IDs should be case-insensitive.

### 4. Committed output files are out of date (low)
- `summary.json`, `scenario.json` and `investigation_results.json` differ from what `python3 analysis.py` writes now. They lack `eligible_deposits`, `affected_records` and `assumption`. `analysis_walkthrough.py` produces this older format, and running it overwrites the newer files.
- The README doesn't mention that the walkthrough rewrites those files.
- **Fix:** re-run `analysis.py` once, and add that note to the README.
