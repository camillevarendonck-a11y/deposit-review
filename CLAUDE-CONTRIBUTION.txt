1. WHAT I BUILT

Deposit Review is a local data-analysis prototype for crypto deposit operations.
It accepts deposit CSV records, applies a user-selected time target, prioritizes
overdue cases, separates missing evidence from recorded events, and suggests
which records an analyst could check next. It includes a hypothetical timing
scenario and a reproducible 1,000-record synthetic demonstration.

ANALYSIS AND CODE REVIEW
Claude was also used to challenge calculations, explanations, assumptions and
validation behavior, through the case responses and project review below.

A. Reviewing the analysis
Claude reviewed the five-record example and the timing scenario. The saved
review record covers checks of the 20% target-attainment rate, 155-minute
completed-only median, and hypothetical improvement to 40%. It identified a
malformed CSV row, exports occurring before validation and the absence of a
not-yet-due test case. Those findings informed subsequent corrections.

B. Reviewing investigation explanations
Three deliberately selected fictional cases were used:
- DEP-003: completed late, with most recorded waiting after confirmation.
- DEP-005: overdue with neither confirmation nor credit evidence recorded.
- DEP-006: unresolved but not yet due; excluded from the eligible denominator.

Claude's first DEP-006 explanation included unsupported reassurance about
normality and an exact-boundary explanation inconsistent with the code. Explicit
feedback clarified that a recorded credit at 120 minutes is within target, while
an unresolved case becomes overdue only after 120 minutes. The revised response
removed the reassurance and applied the boundary correctly. The original and
revised assessment records are both retained. This is one revised case, not
an additional independent evaluation.

C. Reviewing the current project with Claude Code
The latest response reports testing a scratch copy and independently checking
the sample, large demo, filters, queue ordering and export. It also reported an
extreme timestamp error, permissive input formats and outdated saved outputs.
Codex reproduced those issues locally, implemented corrections, refreshed the
exports and added regression checks. After these fixes, 29 Python checks and
3 JavaScript checks passed. A live local request verified that the timestamp
error returns a clear validation response instead of dropping the connection.

5. WHAT THIS DOES NOT CLAIM

- The dashboard does not call Claude's API. There is no live Claude API integration
  or autonomous Claude agent in this prototype. A Claude Code skill and a local,
  read-only MCP server were added on November 13, 2026 (see section 3D); they are
  not part of the dashboard and were tested only as described there.
- Its findings and next-check suggestions use deterministic rules. The displayed
  suggestions are not live Claude-generated answers.
- All demonstration records are synthetic. Their frequencies, timing patterns
  and 50% scenario assumption are deliberately chosen, not company findings.
- No operational time savings, cost savings, causal diagnosis or production
  readiness have been established. Missing records do not prove lost funds.
- Selected case reviews do not establish a statistical model accuracy rate.
- Model IDs and original session timestamps were not supplied. Recorded dates
  in the evidence files describe documentation dates, not authenticated run times.
- Claude's reported tool execution is attributed to the supplied review; the
  full execution logs and original session exports are not in this folder.
